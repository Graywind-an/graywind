# 消化系统 · 嘴 + 消化

两件工具，管**吃进来之前**这一段：怎么判、判到什么程度、报告交给谁。

> English: [README.en.md](README.en.md)

> 2026-10-31 立的规矩：
> **要不要吃由会话上报给人决定，工具不拍板。**
> **组装出来的东西必须先在镜像里装一遍、检验有没有问题，再复制到本体。包括官方插件也走这个流程。**

**一条命令跑全部**（脚本版，不需要 DSH）：

```bash
node 消化系统.mjs 配置                  看配置从哪来、哪些功能降级了
node 消化系统.mjs 尝 <目标>              嘴：只读声明
node 消化系统.mjs 消化 <目标…>           消化：真读源码
node 消化系统.mjs 镜像                  镜像装完的验收门（要起内核，慢）
node 消化系统.mjs 排泄 [--真排 --确认]   排泄：清已装完的垃圾
node _smoke.mjs                        自检：假 ctx 把插件壳跑一遍（37 项）
```

## 一、这两个工具各管一段

| 工具 | 读什么 | 出什么 |
|---|---|---|
| **`核心\尝.mjs`（嘴）** | 只读**声明**：体积（按类型比）、依赖、install 钩子、危险词、仿冒、二进制 | 「有红旗」或「可以进胃」+ 理由 |
| **`消化.mjs`（消化）** | 真读**源码**：暗门、注册面、声明 vs 实际、能干什么、蛋白质候选 | 一份材料 + `.已消化.json` 标记 |

嘴能感觉到的只是"口感、温度、气味"——**毒蘑菇在嘴里感觉不错**，所以更深的判断要等消化。

**留意 ≠ 拦。** 体积超参考值只是提示（极端大的个体也正常——模型几十 G、桌宠带素材都可能有），超了类型上限才升级。

## 一之二、我们的立场：不替人做决定

> 这一段是这套工具最要紧的约定。

- **就算是红，装不装也是你决定。** 我们不给禁令，只给"这是什么"和"有什么后果"。
- 报告里每一类风险都说清**是什么**、**后果是什么**，然后停在那儿。**要不要装，你拍板。**
- **人设/提示词相关的风险排在最前**，因为它改的不是功能，是**说话的人**——装完之后回话的可能就不是原来那个了。这类我们会写得比其他更重。
- 只有一种情况会"挡一下"：你让包管理器直接把东西装进身体、**跳过了整个流程**。那时会停下来告诉你"你还没看过它是什么"，并给出放行方式（命令里加 `--我知道`）。**那不是审批，是提醒你别在没看清的时候按下去。**

## 二、完整流程（缺一环就是"直接吞"）

```
0  视觉 / 听觉        看见或听见"这东西可能有用"（会话说给人听，人点头才去吃）
1  嘴                下载落进 胃/（唯一落点，不管它是什么）
2  食道              传完整了吗（半截 / 损坏 / 解压不开）—— 只管完整性，不管内容
3  胃                只放着。胃没有判断权。
4  消化              这是什么、安不安全、能干什么 → 报告交给会话
5  会话 → 人         **人决定吃不吃、装哪几个**
6  镜像 DSH          先在镜像里装一遍，跑起来看有没有问题
7  本体              镜像验过了，才复制到本体
```

**第 6、7 步不许跳。** 本体永远不是第一个装的地方。官方插件也一样——"官方"不是免检证。

## 三、给外部用户用的前提（重要）

这套流程默认你**有一个虚拟盘 + 一份镜像 DSH**。用之前要自己决定：

- **要不要设镜像** —— 由你定。不设也能用（`尝` / `消化` 都能单跑），但第 6 步就得你自己想办法验。
- **镜像要不要同步复制** —— 由你定。本仓库不带任何同步脚本，也不假设你有。

两个工具**不会强迫你建镜像**，只会在报告里提醒"这一步最好在镜像里做"。

如果只想单独用这两个工具，不需要 DSH：

```bash
# 嘴：只读声明，出「拦 / 放」
node 尝.mjs <路径或包名>

# 消化：真读源码，出材料
node 消化.mjs <目录>

# 给别人用时加 --不记账：不往人家家里写通道
node 消化.mjs <目录> --不记账
```

**退出码**：`0` = 放（没有红，且黄少于两条）；`1` = 暂缓（有一条红，或有两条以上黄）；`2` = 用法错误。可以直接接到 CI 或提交钩子上。

## 四、通道（饱腹感）

吃进去这件事会记一笔：`~/.dsh/notes/饱腹感.jsonl`，一条一行。

三样分得很清，别混：

| 字段 | 是什么 | 对应身体 |
|---|---|---|
| `量` | 吃了多少（文件数 / 字节） | 饱腹感本身 |
| `花费.token` | 真实 API token | **血糖**（花掉的能量） |
| `占上下文预估` | 字节 ÷ 3.5 | **疲惫感**（占了多少上下文） |

`花费` 现在写 `null`——插件里拿不到 DSH 的 usage 就不编数。真实花费要接余额 / usage 数据。

## 五、标记

`消化` 在**胃里的那个目录**落 `.已消化.json`（含时间、结论、红黄计数、工具数）。

- 只在胃里落。插件库 / profile 是"已经装好的部分"，不贴便签。
- 这个标记是给下游用的：**没标记的，说明还没人看过它**。装不装仍是人的决定，但"没看过"和"看过觉得能装"是两件事，别混。

## 五之二、注意事项表（可以带自己的坑进别人的机器）

`~/.dsh/notes/注意事项.json` —— 用户或实际跑这个工具的人自己填的坑清单，消化每次都会读。

```json
{
  "说明": "…",
  "条目": [
    { "模式": "jailbreak|越狱|破限", "级别": "红", "理由": "破甲类，改系统提示词" },
    { "模式": "@someone/bad-plugin", "级别": "红", "理由": "实测偷读 .credentials" }
  ]
}
```

- `模式` 先当正则试，正则坏了就当子串；匹配对象是路径 + 包名 + 声明 + 注册的工具名。
- `级别` 只写 `红` 或 `黄`。
- **推荐让实际跑的人填**——他最清楚自己踩过什么。我只认自己见过的坑，别人的坑必须能回流进来。

另外，消化会读**进食名单**（`~/.dsh/notes/进食名单.json`），告诉你这份东西是**我们自己找来的**还是**别人塞来的**。

## 六、插件版 vs 脚本版

| | 插件版 | 脚本版 |
|---|---|---|
| 入口 | DSH 里注册成工具 `尝` / `消化` | `node 尝.mjs` / `node 消化.mjs` |
| 强制力 | **嘴有 guard**：`pnpm add` / `dsh plugin add` 直接进身体会被拦下 | 没有 guard——只能"我主动用" |

**这条不能混**：脚本版靠自觉，插件版是拦截。要"不靠记着"就必须装插件版。

## 七、一条已知的假阳性（先说出来）

**安全 / 检测类工具会命中自己。** 它们的源码里必然写着 eval(、child_process、jailbreak 这些词——写在正则里当检测规则。所以拿 消化 去扫一个检测器（包括扫它自己），会报一串红。

这在报告里是**故意的**：一条命中只说明「源码里有这个词」，说明不了它是在检测还是在用。证据那行给到 文件:行，由人看。

同理，尝 只在 **package.json 的声明**里判否决线词为红；README 里出现同类词只算「留意」，因为文档里常常只是在举例讲怎么识别。
