# dsh-reasoning-guard · 兜圈子刹车

抓模型「在重复同一段内容、没有进展」的兜圈子行为，在它把上下文烧干之前让它停手、换个方向。

## 先看这一条：它是模型自己的问题

**模型在原地打转，是模型本身的问题**——不是 DSH 的 bug，不是插件装错了，也不是这台机器的环境坏了。

遇到它的正确反应只有一个：**开一个新会话。**

- **不要**让新会话去「修」已经卡住的那个会话。它卡住，是因为上下文已经在重复里泡了太久；在别的地方分析它、翻它的日志、给它补一句、替它删几条——都改不了它内部的状态。
- **不要**试着「提醒」它继续。它不是在偷懒，是已经陷进去了。
- **要**做的：把还需要的信息收出来，**开新会话，从干净上下文重新开始**。

这个工具做的是**在流里把它打断**，省下继续烧的上下文和时间；但它管不了「这个会话已经开了多久」——**开新会话这件事，只能你自己做。**

## 来路

- **2026-10-25**：一次调用里 reasoning 转了 67,172 字符、「做」重复 4,957 次、正文 0 字符，到喊停才落地。v0.1 因此上线（窗口规则 + cancel）。
- **2026-11-01**：一次复盘发现「思考过程里出现了很多单字循环」。查日志发现 v0.1 **上线至今零次 tripped**——它的判据要「连续 5 个 2000 字窗口」（1 万字符），而单字循环通常只有几百到几千字符，**量程不对**。
- **2026-11-01 v0.2**：加三条规则，改流内切断。思路吸收自 `@mrweicodes/dsh-loop-guard` 的公开说明和实测（精确周期 > 熵比、containment > Jaccard），**代码和判据数字都是我们自己的**。
- **2026-11-01 v0.2.1（吸收原版全部能力）**：定下的原则是「原版好的地方也吸收，原版有的我们都要有甚至更好」。补了 identical-chunks（连续相同 chunk 60 次）、escalate 三档（warn/steer/cancel）、resumeAfterBreak（切断后自动续跑）、breakCode、repeatRatio 诊断。**保留我们的窗口规则、fires 预算恢复、可见 text 块、dshLlm 探针。**

## 五条规则，各管一段

| 规则 | 时间尺度 | 抓什么 | 动作 |
|---|---|---|---|
| **窗口**（v0.1） | 跨步骤 | 字汇密度塌了（2000 字符窗口 uniq<50，连续 5 窗） | 按 escalate（默认 steer，兜底 cancel） |
| **相同 chunk**（v0.2.1） | 单次调用内 | 同一 payload 连续 ≥60 次（单字/短词刷屏） | 流内切断 + steer |
| **周期**（v0.2） | 单次调用内、字符级 | 一段短周期在**精确**重复（周期 ≤512、跨度 ≥512、≥2 种字符） | 流内切断 + steer |
| **短语池**（v0.2） | 单次调用内、行级 | 同一批短句重排（重复质量 ≥2048、覆盖率 ≥0.6、集中度 ≥4） | 流内切断 + steer |
| **跨调用**（v0.2） | 步骤之间 | 上一步 distinct 4-gram 被本步包含 ≥0.8（同一结论换说法） | 连续 3 步 → 按 escalate |

规则顺序跟原版一致：相同 chunk → 短语池 → 周期。
两处关键取舍：
- **精确周期 > 熵比**。熵比随长度上升：markdown 表格 0.72、JSON 0.84、真循环 0.92–0.99，差 0.06 没法定阈值；精确周期对表格/日志/JSON 一律是 0。
- **containment > Jaccard**：卡住的模型会「复述上一步 + 补一句」，Jaccard 被新内容稀释，containment 直接报重复。

## 两个接缝

- **`agent/assistant-stream`**（emit）：只能观察 + 反应，是最后手段。窗口规则挂这里。
- **`llm/stream`**（Cordis waterfall）：能改流。相同 chunk / 周期 / 短语池命中时：关掉开着的 text/reasoning 块（补 `block-end`）→ yield `finish{stop}` → steer 一条纠正（可选 resumeAfterBreak 自动续跑）。
  - 为什么 `stop` 不用 `error`：error finish 会让 `step()` 不产 `assistant/message`，UI 渲染直接崩，而且 turn 在报错分支抛出去，steer 进来的纠正没人认领——看起来就是「它突然停了」。
  - 有 tool-call 块开着时不切（半截 JSON 会被执行）。
  - 消息里没有可见正文时补一个 text 块——只有 reasoning 块的 assistant 消息可能被宿主当成空回复重试。

## 已知边界（2026-11-01 审出来的，接受）

- **完全相同的短行重复 32+ 次也算重复**（`|  |  |`、同一句日志刷屏）。那是刷屏，切掉是对的；但空表格/同构 JSON 如果恰好整行相同，也会被切。挡单字符周期的护栏是 `cycleMinDistinct=2`（单字符靠 tailRun 守卫挡）。
- **真机一次完整切断没跑过。** 上面三个测试都不走真实宿主路径；「只有 reasoning 块的 message 会不会被宿主当空回复」这类问题只有真机能暴露。所以代码里补了可见 text 块（`CUT_NOTICE`）作为加固，但**没有真机证据**。
- `source.kind: 'reasoning-guard'` 不在宿主 `MessageSource` 的封闭联合里（全 asar 零命中）。`createMessage` 不校验，所以进日志没问题；durable 恢复/投影/前端按 kind 分派的那条路**未验**。
