# stallguard · 单字循环检查（复活包里的独立脚本）

**它是脚本，不是插件。** 双击 `check.cmd` 或 `node analyze.mjs` 就能跑，不需要 DSH、不需要加载任何插件——这是它放在复活包里的原因：DSH 起不来的时候，它照样能看会话里有没有「兜圈子」。

## 它查什么

和插件 `dsh-reasoning-guard`（消化系统里叫 `stallguard`）同一个检测器（`detector.js` 是同一份代码拷来的），四条规则：

| 规则 | 抓什么 |
|---|---|
| 窗口 | 2000 字符窗口里不重复字符 <50、连续 5 窗（字汇密度塌了） |
| 周期 | 尾部一段短周期在**精确**重复（周期 ≤512、跨度 ≥512、≥2 种字符） |
| 短语池 | 同一批短句重排（重复质量 ≥2048、覆盖率 ≥0.6、集中度 ≥4） |
| 跨调用 | 上一步 distinct 4-gram 被本步包含 ≥0.8（同一结论换说法） |

**注意**：`identical-chunks`（同一 payload 连续 60 次）是**流式规则**，离线读整块消息测不出来——它只在插件运行时生效，这里不重复实现。

## 怎么跑

```
node analyze.mjs                扫全部会话
node analyze.mjs --session ab12 只扫 id 前缀是 ab12 的
node analyze.mjs --json         机器可读
```

双击 `check.cmd` 也行（它会开一个窗口、跑完停住等你看）。

## 输出怎么读

```
会话        步数  窗口触发  周期触发  池触发  跨调用触发
session-a  583        0      3305  4496:推理        0
```

- **触发** = 这条规则认为那一步在重复；`周期触发` 和 `池触发` 后面的数字是会话事件序号（可以拿去会话文件里定位）。
- **零触发是正常的**，正常会话不会报。
- 一个会话大量触发、而你知道它当时在打转 → 那一步就是当时该被拦却没拦的地方。

## 和插件的关系

| | 插件（stallguard 插件版） | 这个脚本 |
|---|---|---|
| 什么时候 | **活着的时候**——挂 `llm/stream`，模型一循环就切 | **事后**——会话已经跑完 |
| 触发方式 | **被动**（自动） | **主动**（人跑 / 装前标定） |
| 依赖 | 要 DSH 加载 | 零依赖，node 直接跑 |

**两个都要**：插件是闸，脚本是尸检和标定。插件改阈值之前，先拿这个脚本在真实会话上量一遍误报。
